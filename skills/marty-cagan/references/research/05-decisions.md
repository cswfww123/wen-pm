## Decision Logic Pattern

1. If an activity is only output production, classify it as project/feature model.
2. If a PM cannot own value and viability, the role is misdefined.
3. If risk exists, test before delivery.
4. If AI makes building cheaper, invest more in discovery quality, not more output.
5. If a company wants innovation, leadership must give teams hard problems and room to solve them.

## Contradictions / Tensions

### Builder but not sole decider

Cagan increasingly calls PMs builders/creators, but also says PM is not the sole decider. The tension is productive: PM must contribute deeply without replacing design/engineering judgement.

### Universal principles vs messy context

He searches for common principles used by strong product companies, but organizations often differ in maturity, regulation, incentives, and founder involvement.

### Ruthless standards vs coaching belief

He is harsh on weak PM work, yet his coaching stance assumes product sense can be built. The skill should not simply kill ideas; it should kill the lazy version and build a discovery path for the promising version.
